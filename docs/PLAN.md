# План

## Этап 1 — Источник данных ✅ (основной способ выбран: A)

Цель: надёжно получать список тренировок из календаря Training Endurance (план + по возможности факт)
на бесплатном аккаунте.

1. **Собрать варианты** — [options.md](01-data-source/options.md). ✅
2. **Дешёвые проверки** (минуты, без кода): встроенный экспорт/iCal в настройках TE, разбор сетевых запросов
   веб-приложения, письмо разработчику. ✅ B и A проверены; письмо (G) не отправляли — больше не обязательно.
3. **Прототипы** для 1–2 лучших вариантов: скрипт, который логинится и выводит тренировки на неделю.
   ✅ [`tools/te-probe`](../tools/te-probe/README.md)
4. **Решение** — [DECISION.md](01-data-source/DECISION.md): основной способ и запасной. ✅ основной — A

Готово, когда: есть скрипт/прототип, который по нашим учётным данным стабильно отдаёт тренировки
на ближайшие 7 дней (дата, вид спорта, название, длительность/дистанция, статус), и понятно, как
обновлять авторизацию.

## Этап 2 — Модель данных и слой синхронизации (черновик)

- Формат `Workout`, который нужен виджету.
- Где живёт логика получения данных: в iOS-приложении (App Group + Keychain) или на своём сервере.
  После этапа 1 склоняемся к iOS-приложению: вход один раз, токен живёт ~3 года, свой сервер не нужен.
- Длительность тренировки: брать `plan.duration`, а если он пуст — считать по шагам `struct`.
- Частота обновления с учётом бюджета WidgetKit (обычно 40–70 обновлений в день).

## Этап 3 — iOS-приложение + WidgetKit (черновик)

- Приложение-контейнер: вход в аккаунт, настройки.
- Размеры виджета: small (сегодня), medium (сегодня + завтра), large (неделя), lock screen (accessory).
- Интерактивность (iOS 17+): например, «открыть тренировку в TE».

## Этап 4 — Сборка, подпись, установка (черновик)

- Нужен Mac с Xcode и Apple ID. Для личного использования хватит бесплатного профиля
  (переподписывать раз в 7 дней), с Apple Developer Program ($99/год) — без этого ограничения.
