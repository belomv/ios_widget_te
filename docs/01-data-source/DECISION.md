# Этап 1 — решение по источнику данных

**Статус:** принято 2026-09-25 (основной способ). Запасной под вопросом.

| | Способ | Почему |
|---|---|---|
| Основной | A: GraphQL + нативный вход Kratos | Работает на бесплатном аккаунте (проверено), полные данные (план/факт, вид спорта, структура), сессия ~1000 дней, без своего сервера |
| Запасной | F: вход через WKWebView → тот же токен | Если парольный вход сломают или появится капча. B (Google Calendar) на бесплатном аккаунте не выгрузил ни одной тренировки |
| Дополнительно (факт) | Не нужно | Выполненные тренировки TE сам подтягивает из Strava/Garmin/Coros и отдаёт в `fact` того же запроса |

## Как это работает (для этапа 2)
1. Вход: `GET /kratos/self-service/login/api` → `POST <ui.action>` с email и паролем → `session_token` (~1000 дней).
2. Данные: `POST /graphql` с заголовком `x-session-token`, запросы `getMe` (userID) и `calendarItems` (список дат).
3. Токен истёк или отозван (`ErrAccessDenied`) → войти заново тем же логином и паролем из Keychain.

Детали и поля ответа — в [эксперименте A](experiments/A-private-web-api.md), рабочий пример — [`tools/te-probe`](../../tools/te-probe/README.md).

## Риски
- API недокументированный: может поменяться без предупреждения. Разбор ответа делаем терпимым к изменениям.
- Условия использования TE не читали и разрешения не спрашивали (G). Для личного виджета с редкими запросами
  риск небольшой, но письмо разработчику всё ещё имеет смысл.

## Отброшенные варианты
- **B (Google Calendar)** — интеграция подключается, но на бесплатном аккаунте ничего не выгрузила.
- **J (официальный OAuth/MCP)** — только для PRO и платных тренеров. Вернуться, если тариф сменится.
- **D (WorkoutKit/HealthKit для плана)** — предварительно: сторонние приложения не видят чужие
  запланированные тренировки. Подтвердить по документации Apple.
