# Этап 1 — варианты получения данных из Training Endurance

Исходные условия: бесплатный аккаунт, публичного API нет (по результатам поиска), есть веб-приложение
`app.trainingendurance.com` и мобильные приложения. Данные нужны в iOS-виджете (WidgetKit), который
сам обновляется по расписанию и умеет делать сетевые запросы.

## Сводка

**Порядок проверки:** B и G (почти бесплатно) → A (разбор запросов веб-приложения) → в зависимости от
результата: A на телефоне напрямую, E поверх A, или F.

**Обновление 2026-09-25:** A разобран без входа: GraphQL `app.trainingendurance.com/graphql`, вход через
нативный API-поток Ory Kratos, токен в `x-session-token` (сессия ~1000 дней). Прогон на бесплатном аккаунте ✅. iCal нет; выгрузка в Google Calendar (B) подключается, но ничего не выгрузила.
Официальный OAuth/MCP существует, но только для PRO (J). Подробности в [эксперименте A](experiments/A-private-web-api.md).

## B. Встроенный экспорт календаря

**Итог (2026-09-25): ❌** iCal нет; интеграция с Google Calendar подключается, но ничего не выгрузила
([эксперимент B](experiments/B-builtin-export.md)).

**Идея.** Многие платформы (TrainingPeaks, TrainerRoad, intervals.icu) дают iCal-ссылку на календарь,
иногда даже на бесплатном тарифе. Если в TE она есть, всё просто: виджет качает `.ics` и разбирает его,
либо календарь подписывается в iOS «Календаре» и читается через EventKit.

**Как проверить.** Посмотреть настройки профиля, календаря, интеграций и «Поделиться» в веб-версии
и мобильном приложении. Посмотреть, есть ли экспорт в Google Calendar.

**Плюсы:** официальный путь, нет авторизации (секрет в самой ссылке), не ломается.
**Минусы:** в iCal обычно мало деталей (название + описание); может быть только на платном тарифе.

## A. Приватный API веб-приложения

**Итог (2026-09-25): ✅ выбран.** GraphQL + нативный вход Kratos, работает на бесплатном аккаунте.

**Идея.** `app.trainingendurance.com` почти наверняка SPA, которое берёт календарь JSON-запросами
к своему бэкенду с токеном (JWT / cookie). Эти же запросы можно повторить из iOS-кода.

**Как проверить.** DevTools → Network → Fetch/XHR, открыть календарь, пролистать неделю, сохранить HAR.
Найти: эндпоинт входа, вид токена и срок жизни, наличие refresh-токена, эндпоинт календаря
(параметры дат) и формат ответа. Подробно: [experiments/A-private-web-api.md](experiments/A-private-web-api.md).

**Реализация на iOS.** Приложение-контейнер логинится и сохраняет токен в Keychain с общей access
group. Виджет в `TimelineProvider` сам делает запрос и строит timeline на день или неделю вперёд.

**Плюсы:** полные данные, как в самом приложении; работает без своего сервера.
**Минусы:** недокументированный API может поменяться; вопрос с условиями использования; если вход
через Google/Apple OAuth или с капчей — сложнее (тогда поможет F для первого входа).

## J. Официальный OAuth 2.1 / MCP-сервер

**Идея.** У TE есть официальный MCP-сервер `mcp.trainingendurance.com` с OAuth 2.1 (Ory Hydra на
`oauth.trainingendurance.com`: PKCE, Dynamic Client Registration, device code, скоупы `training:read`,
`offline_access`). Это документированный и разрешённый путь с refresh-токенами.

**Почему нет (пока):** по словам самого сервера, доступ только у PRO-атлетов и платных тренеров,
бесплатному аккаунту после входа вернётся 403. Становится лучшим вариантом, если владелец перейдёт на PRO.
Можно спросить разработчика (G), пускает ли `/graphql` OAuth-токены со скоупом `training:read`.

## G. Попросить у разработчика

**Идея.** Сервис небольшой (разработчик — Artem Smirnov, есть русская версия сайта). Можно
попросить read-only API-токен, iCal-ссылку или разрешение пользоваться внутренним API.

**Плюсы:** стоит одно письмо; легализует вариант A. **Минусы:** ответ может не прийти.

## E. Свой сервер-посредник

**Идея.** Cron (GitHub Actions / Cloudflare Worker / VPS) раз в N минут логинится в TE (как в A,
или через headless-браузер), нормализует данные и публикует приватный JSON и/или `.ics` по секретной
ссылке. Виджет читает этот JSON. Бонус: `.ics` можно подписать в Календаре на iPhone, Mac, где угодно.

**Плюсы:** логику парсинга можно чинить без пересборки iOS-приложения; можно использовать headless-браузер;
одна ссылка — и на виджет, и на календарь. **Минусы:** учётные данные хранятся на сервере; ещё одна
движущаяся часть.

## F. Встроенный WKWebView и извлечение данных

**Идея.** В приложении открывается `app.trainingendurance.com` в WKWebView, пользователь входит как обычно
(любой способ, включая OAuth). Дальше либо забираем токен из cookies/localStorage и продолжаем как в A,
либо перехватываем fetch-ответы через внедрённый JS, либо разбираем DOM календаря.

**Плюсы:** снимает любые сложности со входом. **Минусы:** разбор DOM хрупкий; виджет не может сам
открыть WebView, поэтому данные обновляются, только когда запущено приложение (или через фоновое
обновление `BGAppRefreshTask`, а это нечасто и без гарантий).

## C. Через Garmin Connect

**Идея.** TE умеет экспортировать тренировки в Garmin. Если плановые тренировки попадают в календарь
Garmin Connect, их можно читать оттуда: неофициальный API (например,
[python-garminconnect](https://github.com/cyberjunky/python-garminconnect)) или экспорт календаря Garmin.

**Минусы:** двойная цепочка (TE → Garmin → мы), нужен Garmin; официальный
[Garmin Training API](https://developer.garmin.com/gc-developer-program/training-api/) только для
партнёров и в основном на запись; вход в Garmin из кода капризный (MFA, изменения SSO).
Смысл есть, только если Garmin уже используется.

## D. Через Apple Watch / WorkoutKit / HealthKit

**Идея.** TE экспортирует тренировки на Apple Watch, скорее всего через WorkoutKit (`WorkoutScheduler`).
**Почему скорее всего нет:** `WorkoutScheduler` показывает приложению только тренировки, которые
запланировало оно само. Чужие запланированные тренировки сторонним приложениям недоступны. В HealthKit
лежат только выполненные тренировки. Проверку сводим к одному факту из документации Apple, без кода.

## I. Выполненные тренировки: Strava / HealthKit

Для части «факт» (что уже сделано сегодня, сколько за неделю) данные можно брать не из TE, а из HealthKit
(виджет через приложение-контейнер) или Strava API (официальный, бесплатный). Это дополнение к варианту
«план», не замена.

## H. Вручную

Шорткат iOS, который получает текст или скриншот календаря (OCR через Vision) и складывает его в App Group.
Только если всё остальное не сработает.

## Риски, общие для всех вариантов

- **Условия использования TE.** Перед тем как делать A/E/F «в прод», прочитать ToS; лучше получить явное
  разрешение (G).
- **Лимиты WidgetKit.** Виджет обновляется, когда решит система (обычно раз в 15–60 минут). Для календаря
  тренировок этого хватает: строим timeline на день или неделю вперёд из одного запроса.
- **Секреты.** Токены — только в Keychain на устройстве или в секретах сервера, никогда в git.
